# ADR-004: 后台路由前缀 `/admin`，响应包络沿用源站四字段但扩展错误码

## Status: Accepted (2026-07-19)

## Background

既有约定（实测确认，必须对齐而非另起一套）：

- 路由表 `route/app.php` **无统一前缀**，路径直接照源站 `api.shengtai.cyou` 真实 URL 定义（`/item`、`/order/:id`、`/nft/secondary/:iid`）
- 动态段风格为 `:iid` / `:id` / `:gid` / `:uid`，且**同类动态段统一约束 `\d+`**（`route/app.php:54` 用 `->pattern(['iid' => '\d+'])`，注释说明这是为了避免静态段被动态段抢匹配）
- 响应包络固定四字段 `{status, code, message, data}`，由全局 `ResponseMiddleware` 产出，**HTTP 状态码一律 200**
- 错误码仅 5 个常量（`app/exception/ApiException`）：`0` 成功 / `10100` 参数缺失 / `10101` 参数类型 / `10203` 未找到 / `11111` 请先登录 / `20000` 系统错误
- 兜底 `Route::miss` 返回 `10203`
- 参数读取统一走 `app/controller/Base.php` 的 `need` / `needInt` / `str` / `int` / `bool` / `body` / `bodyNeed`，缺失即抛 `ApiException::missing($field)`，message 形如 `iidmust not be null`（**无空格**）
- ID 一律以**字符串**返回（`Transformer::id` / `Base::idStr`），时间戳为 **13 位毫秒数字符串**（`Base::ts`）

## Decision

### 1. 路由前缀

后台路由**自带 `/admin` 前缀**，写在 `route/admin.php`（8922 进程独立加载）。这与 C 端"无前缀"不同，理由：

- 后台**没有源站契约可对齐**，前缀是纯自主设计，必须有隔离标识防止误把后台端点当 C 端端点调用
- `admin-web` 的 vite proxy 用 `'/admin-api' → 8922` 并 rewrite 掉 `^/admin-api`，实际打到后端的路径是 `/admin/xxx`，前后端两侧各留一半可读性，proxy 配置注释能一眼看懂

命名风格严格沿用 C 端：**小写驼峰段名 + 冒号动态段**。

```
admin/auth/signin                    —— 段名小写驼峰，无 /api，无驼峰大写段
admin/item/:iid                      —— 冒号动态段，风格同 C 端 /nft/secondary/:iid
```

### 2. 响应包络

**沿用 `{status, code, message, data}` 四字段不变。** 后台前端 `axios` 响应拦截器按 `res.status` 判定成败，逻辑与 C 端一致（这也是复用 `ResponseMiddleware` 的前提）。

`ResponseMiddleware` 是**全局中间件**，后台 8922 进程同样会加载它。它的 `isEnvelope()` 判定（恰好四键 + `status` 为 bool + `code` 为 int）在后台同样适用，后台**不得返回恰好形如 `{status,code,message,data}` 的业务数据**（后台无此需求，天然不会撞）。

### 3. 错误码扩展

后台需要区分 C 端没有的语义（未授权 / 权限不足 / 会话失效 / 冲突）。**不改动 `ApiException` 现有 6 个常量**（C 端 93 个端点依赖），新增 4 个：

| 常量 | 值 | 含义 | 后台前端行为 |
|---|---|---|---|
| `CODE_UNAUTHORIZED` | `11111` | 未登录 / 会话失效（**复用现有常量**） | 清 token 跳登录页 |
| `CODE_FORBIDDEN` | `14003` | 权限不足（角色无该权限码） | toast「无权限」，**不跳登录** |
| `CODE_SESSION_REVOKED` | `14001` | 会话被登出 / 被顶号 | 清 token 跳登录页 + toast |
| `CODE_CONFLICT` | `14009` | 写冲突（乐观锁失败 / 状态已变更） | toast 提示刷新 |

**不新增 HTTP 状态码语义**，保持与 C 端一致的「HTTP 200 + 业务码」范式。这是为了让后台前端能复用同一套 axios 拦截器骨架，减少认知负担。

### 4. 分页

C 端 `pageList($rows, $total, $withTotal)` 默认返回**裸数组**（因为源站实测多数端点如此）。后台前端是自己写的、契约自主可控，因此**后台统一强制返回 `{list, total, pageNo, pageSize}`**——不复用 `pageList` 的裸数组分支，避免踩已记录的坑（`app/controller/Base.php:120-133` 注释里的「`.map is not a function`」白屏事故）。

分页参数沿用 `pageNo` / `pageSize`，`pageSize` 上限 100 沿用 `Base::pageSize()` 的钳制。

### 5. `Route::miss`

后台 `Route::miss` 返回 `10203` + message「未找到」，与 C 端一致。**不返回后台新错误码**，避免前端把「路径打错」误判成业务错误。

## Consequences

正面：
- 前后端两侧各留 `/admin` 一半标识，proxy 与后端路由表都自解释
- 包络与错误码风格与 C 端统一，前端 axios 拦截器可复用改造
- 分页形态固定为 `{list,total,pageNo,pageSize}`，避免裸数组/对象混用的历史坑

负面 / 必须注意：
- **后台不能直接复用 `app/controller/Base.php`**：它假定 uid 来自 `request->auth_uid`（C 端用户），且 `pageList` 默认裸数组。必须新建 `app/admin/controller/BaseAdmin.php`，继承 TP 的 `BaseController`（只借 `validate`），**不继承 C 端的 `controller\Base`**（或继承但覆盖 `uid()`/`pageList()`——推荐前者，避免语义混淆）
- 路由顺序仍受 ThinkPHP「首匹配即命中」约束：同一 group 内静态段必须排在动态段之前。写路由时若出现 `admin/item/:iid` 与 `admin/item/stats` 并存，`stats` **必须**写在前面。这条已被 `route/app.php:43-54` 的历史注释证实过，必须内嵌到 `route/admin.php` 的注释里
- 新增 4 个错误码常量必须写在 `ApiException` 的**独立区块**并注明"C 端不用，后台专用"，防止后人误以为可全局使用
