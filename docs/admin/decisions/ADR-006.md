# ADR-006: 图标库锁定 lucide-vue-next 1.0.0，尺寸 16/20/24px

## Status: Accepted (2026-07-19)

## Background

后台需要图标：菜单项、表格操作列、状态标记、空态、审核通过/驳回标记。当前项目情况：

- C 端 `/workspace` 使用 Vant 4.9，其内置图标是**字体图标**（`van-icon` + iconfont 字体文件），不是 SVG
- 后台是桌面端密集布局，需要一套线性风格一致的 SVG 图标

团队 P0 规则明确要求：技术栈选型必须锁定一套 SVG 图标库，尺寸规范 16/20/24px，全项目统一不得混用；禁止用 emoji 充当功能图标。

## 候选方案对比

| 方案 | 版本（已核验） | 开发成本 | 视觉一致性 | 包体积 | 结论 |
|---|---|---|---|---|---|
| **lucide-vue-next** | 1.0.0（npm latest，已核验 peerDeps `vue: >=3.0.1`） | 低。`import { Search } from 'lucide-vue-next'` 直接用，Vite 按需 tree-shake | 高。线性风格统一，全集约 1500 个图标，24px 网格设计 | 仅打包用到的图标，实测几十个图标约 30-60KB | **采纳** |
| Element Plus Icons | 2.3.2 | 中。需装 `@element-plus/icons-vue` 并配 Element Plus 体系 | 中。填充风格，与 Vant 桌面形态可混但需额外适配 | 全量引入约 200KB+ | 否决。引入 Element Plus 会带来第二套组件库，与"Vant 一套走到底"冲突 |
| Heroicons | 2.2.0 | 中。outline/solid 双风格需自选 | 高 | 小 | 否决。Vue 官方无第一方包，第三方封装质量参差 |
| Vant 内置字体图标 | 4.9.15 | 最低 | 低。字体图标无法继承 `currentColor` 之外的颜色状态，做不了"驳回=红、待审=黄"的语义色 | 字体文件 200KB+ | 否决。字体图标不是 SVG，违反"锁定一套 SVG 图标库" |

## Decision

**锁定 `lucide-vue-next@1.0.0`，作为后台唯一图标来源。**

尺寸规范（唯一允许的三档，禁止其他值）：

| 尺寸 | 用途 |
|---|---|
| 16px | 表格行内操作图标、输入框前置图标、标签内图标 |
| 20px | 菜单项图标、卡片标题图标、Tab 图标 |
| 24px | 空态插图图标、页面级功能入口图标、状态大标记 |

使用约束（写进代码评审检查项）：

1. **只允许通过 `lucide-vue-next` 导入**，禁止手写内联 `<svg>` 路径（唯一例外：品牌 Logo 本身）
2. **颜色一律走 CSS Token**（`currentColor` 或 `var(--token-*)`），禁止硬编码色值。唯一例外是 `#fff` / `#000`
3. **禁止用 emoji 代替任何功能图标**，包括空态、状态标记、菜单项
4. `stroke-width` 统一 1.75（lucide 默认 2，降低一档在 16px 下更清晰）
5. 图标必须带 `aria-hidden="true"`（装饰性）或 `aria-label`（可点击独立按钮），无障碍不允许裸图标按钮

## Consequences

正面：
- 视觉体系统一，不会在后期出现"这个图标是另一套"的割裂
- tree-shaking 有效，包体积可控
- 与 Vant 4.9 可共存：Vant 组件内部的字体图标不替换（那是组件库自带，不是我们选型的图标体系），后台**自绘的**图标一律 lucide

负面 / 必须注意：
- lucide 1.0.0 是较新的大版本（0.x 长期演进后转 1.0），需锁定精确版本号 `1.0.0` 而非 `^1.0.0`，避免后续 1.x 变更图标 path 造成视觉回归
- lucide **没有品牌图标**（微信/支付宝等）。若后台需支付渠道图标，只能从别处取，此时须走"单一例外登记"流程，不得混用第二套图标库
