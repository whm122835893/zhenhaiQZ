# ADR-001: 后台前端采用独立工程 `admin-web/`

## Status: Accepted (2026-07-19)

## Background

C 端 H5 与后台在构建形态、路由模式、产物形态、视觉体系四个层面全部冲突：

| 维度 | C 端 `/workspace` | 后台需求 |
|---|---|---|
| 构建产物 | 单个自包含 HTML（9.3MB，`vite-plugin-singlefile` + `inlineDynamicImports:true`） | 常规多 chunk，按需加载 |
| 路由 | hash 模式（源站是静态单页，无服务端路由能力） | history 模式（后台需要可分享 URL 与浏览器前进后退） |
| 组件库 | Vant 4.9 移动端组件（375px 视口、`postcss-px-to-viewport-8-plugin` 把 px 转 vw） | Vant 4.9 桌面端形态（`postcss-px-to-viewport` 必须去掉，否则后台所有间距被压成 vw，在 1440px 屏上全部错版） |
| 依赖 | axios 1.7 | axios 1.7（可对齐） |

若把后台放进同一工程，必须为后台单独拆一份 vite 配置（`singlefile` 开关、`px-to-viewport` 插件开关、router history/hash 模式都是**构建期全局量**，不是按目录生效的）。这意味着 `vite.config.js` 要变成一份带条件分支的配置，并且**任何一次针对后台的构建调整都有污染 C 端产物的风险**——而 C 端产物是逐像素复刻的验收基线，一旦被破坏，回归成本极高。

## Decision

在 `/workspace/admin-web/` 建立**独立工程、独立 `package.json`、独立 `vite.config.js`、独立 `node_modules`**，与 C 端物理隔离。

版本锚定（与 C 端对齐，不跨大版本）：

| 依赖 | 版本 | 说明 |
|---|---|---|
| vue | 3.5.13 | 与 C 端同 minor |
| vite | 6.0.7 | 与 C 端同 minor |
| @vitejs/plugin-vue | 5.2.1 | 与 C 端同 minor |
| vant | 4.9.15 | 与 C 端同 minor |
| pinia | 2.3.0 | 与 C 端同 minor |
| vue-router | 4.5.0 | 与 C 端同 minor |
| axios | 1.7.9 | 与 C 端同 minor |
| lucide-vue-next | 1.0.0 | **图标库锁定项**，全后台唯一图标来源 |
| echarts | 6.1.0 | 只读看板图表 |
| @vueuse/core | 15.0.0 | 组合式工具（非必需，按需引入） |

关键：**不引入** `vite-plugin-singlefile`，**不引入** `postcss-px-to-viewport-8-plugin`。

## Consequences

正面：
- C 端 `vite.config.js` 一个字符都不动，vite 构建门禁（`npm run build` 产物大小回归）完全隔离
- 后台可自由加 `vite-plugin-compression`、source map 策略、分包配置
- 两套 `node_modules` 独立，C 端升级依赖不会连带后台

负面：
- 两份 `package.json`，Vant / vue 等公共依赖磁盘重复（约 +80MB）
- 公共代码无法直接复用：后台与 C 端**零共享源码**，任何共享需求（如统一的金额格式化）需各自实现或后续抽第三方包；MVP 阶段接受这个重复
